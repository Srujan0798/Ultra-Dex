# Ultra-Dex v6.0.0 Release Notes

## Highlights

Ultra-Dex v6.0.0 expands the platform from orchestration-only into a broader ecosystem release focused on marketplace extensibility, enterprise onboarding, compliance/SLA controls, and dashboard visibility.

### Major capabilities

1. **Dashboard expansion**
   - Task history and detail workflows
   - Agent monitoring and configuration panels
   - Memory tier exploration and bulk operations
   - Cost analytics charts and ROI visualization
2. **Marketplace workflows**
   - Search/install/uninstall/update commands
   - Publish and rating flows for community packages
3. **Enterprise initialization**
   - License-gated enterprise bootstrap
   - SSO provider integration (Okta, Azure AD, Auth0, Generic OIDC)
   - SLA compliance model and breach alert hooks
4. **Compliance and reliability**
   - Audit export/retention foundations
   - Improved release gate hardening (perf/test/lint/typecheck/build)

## Migration Guide (v5.0.0 → v6.0.0)

### 1. Upgrade package

```bash
npm install -g @ultra-dex/cli@6.0.0
```

### 2. Validate environment

Ensure your `.env` includes current runtime values for:
- `MEMORY_BACKEND`
- `REDIS_URL` (if using redis mode)
- `DATABASE_URL` (if using postgres-backed features)

### 3. Re-run local gates

```bash
npm run typecheck
npm run lint
npm test
npm run test:perf
```

### 4. Verify CLI surfaces

```bash
npm start -- marketplace --help
npm start -- enterprise --help
npm start -- perf profile --help
```

## Breaking Changes

- No hard protocol-breaking API removals were introduced intentionally in this release.
- Operationally, marketplace and enterprise command paths are now expected in release validation; legacy manual-only plugin install flows are no longer the primary documented path.

## Known Issues

- Some enterprise subcommands still depend on optional enterprise runtime packages in advanced environments.
- Dashboard App Router page scaffolding exists in parallel with Vite runtime pages while migration is in progress.
- Postgres/Redis integration tests require corresponding services and env vars; otherwise they skip gracefully.
